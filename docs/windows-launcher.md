# Windows 一键启动与验证

## 使用方式

安装 Node.js 20.9 或更新版本（包含 npm），将整个项目解压到本地文件夹，然后双击 `启动.bat`。启动器使用系统自带的 Windows PowerShell 5.1，首次运行或缺少 Next.js 启动文件时自动执行 `npm install`。

服务固定使用 `127.0.0.1:3000`。启动器同时确认本次启动的进程仍在运行、3000 的监听进程属于本次启动的进程树、首页返回 HTTP 2xx，然后自动打开浏览器。浏览器无法自动打开时会显示手动访问地址。

保留启动窗口以查看日志，关闭窗口可停止本次服务。启动器不自动结束任何进程，也不自动删除 `.next` 缓存。端口已被占用时会直接报错；如果是已启动的本项目，请使用原窗口。如果是其他程序，请确认后自行关闭它再重试。不会自动切换端口，`PORT` 环境变量也不会覆盖这里的显式端口。

安装失败或服务提前退出时会返回非零状态；就绪等待默认 90 秒，HTTP 探测每次最多 2 秒。超时或无法确认进程归属时不会打开浏览器。超时后服务可能仍在运行，请检查日志并关闭启动窗口后再试，避免重复启动。

## 手动验证

使用测试副本操作，先确认 3000 空闲。

1. **首次启动**：在尚无 `node_modules` 的副本中双击 `启动.bat`。应先安装依赖，出现 Next.js 日志，页面成功响应后打开 `http://127.0.0.1:3000`。
2. **再次启动**：关闭启动窗口，确认服务已停止，再双击。应跳过安装并正常打开页面。也可从其他目录执行批处理，或放入含中文及空格的目录，确认仍使用脚本所在项目。
3. **重复双击**：服务运行时再次双击。新窗口应提示 3000 被占用，原页面和原服务应保持可用。
4. **无关程序占用**：关闭本项目服务，在另一个终端运行下列临时服务，再双击启动脚本。应提示端口冲突，且临时服务仍返回 `unrelated`。测试结束在临时服务终端按 Ctrl+C。

   ```powershell
   node -e "require('http').createServer((req,res)=>res.end('unrelated')).listen(3000,'127.0.0.1')"
   ```

5. **相似端口不误判**：把上面的 `3000` 改为 `30000`。本项目仍应在 3000 正常启动，临时服务不受影响。
6. **启动失败**：在测试副本中暂时把 `package.json` 的 `scripts.dev` 改成 `node -e "process.exit(7)"`，双击启动。应提示服务在就绪前退出并保留日志，不应打开浏览器。验证后恢复原值 `next dev`。
7. **安装失败、HTTP 错误及无响应**：运行下面的自动测试。测试用隔离副本模拟安装失败、HTTP 500 和无响应，并确认没有就绪提示、等待有超时限制、失败安装留下部分依赖目录后仍可重试。

## 自动回归测试

在 Windows 项目目录执行：

```powershell
node --test tests/windows-launcher.test.mjs
```

测试需要 Node.js 和 Windows PowerShell 5.1，使用真实 Windows 进程及 TCP 连接，在临时目录模拟 npm 和开发服务器，不依赖外部网络或实际 Next.js 编译。测试开始前请关闭本项目服务并确保 3000、30000 空闲；已有监听器时测试会拒绝继续，不会结束它。测试仅清理自己创建的进程。

若只想检查真实项目启动而不打开浏览器，可运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-windows.ps1 -NoBrowser
```

可通过 `-StartupTimeoutSeconds 10` 缩短排查时的就绪等待；正常使用双击批处理即可。直接运行 PowerShell 脚本时，超时后若服务仍存活，请关闭承载它的终端窗口。
